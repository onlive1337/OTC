# Обновление OTC 1.8.4

Обновление подготовлено для Python 3.14. Схема SQLite не меняется,
пользовательские настройки сохраняются. Новые пользовательские функции не добавлены.

## Зависимости

Проверены по PyPI 29 сентября 2026 года:

- aiogram 3.27.0 → 3.31.0, поддержка Telegram Bot API 10.3.
- aiohttp 3.13.5 → 3.14.3.
- python-dotenv 1.2.2 → 1.2.3.
- ujson 5.12.0 → 6.0.0. Удалённая в 6.0 поддержка некоторых bytes-like объектов
  проектом не используется: JSON поступает в виде строк.
- aiosqlite 0.22.1 и uvloop 0.22.1 оставлены: это актуальные релизы.
- pytest 9.1.1 вынесен в requirements-dev.txt и не устанавливается в production.

constraints.txt фиксирует также транзитивные версии проверенного окружения.
Он применяется автоматически через requirements.txt; сам по себе не устанавливает
перечисленные пакеты, поэтому тестовые инструменты не попадают в runtime.

Источники: [aiogram](https://docs.aiogram.dev/en/latest/changelog.html),
[aiohttp](https://pypi.org/project/aiohttp/),
[python-dotenv](https://pypi.org/project/python-dotenv/),
[ujson 6.0](https://github.com/ultrajson/ultrajson/releases/tag/6.0.0).

## Что изменено

- Параллельные обновления курсов разделяют одну задачу. При отказах действует
  пауза 30 секунд; всё обновление ограничено 25 секундами.
- Отмена запроса пользователя не отменяет общую загрузку курсов.
- Убраны повторные одиночные запросы в CoinGecko после пакетного запроса
  с собственными повторами. CoinCap остаётся резервным источником при наличии ключа.
- Уже полученные курсы обычных валют сохраняются даже при тайм-ауте криптосервиса.
- Ошибки HTTP 400/401/403/404 не повторяются; 408/429/5xx повторяются в пределах лимита.
- Для Telegram 429 повторяется только отклонённый API-метод. Предыдущие ответы,
  записи в базу и весь обработчик заново не выполняются.
- Inline-кэш Telegram стал персональным: язык и выбранные валюты одного пользователя
  не используются для другого пользователя с тем же запросом.
- Одновременно обрабатывается до 100 обновлений Telegram. Настройка:
  `POLLING_CONCURRENCY` в окружении или `.env` при запуске через Compose.
- Остановка завершает общую загрузку курсов до закрытия HTTP-сессии.

Курсы по-прежнему кэшируются на 10 минут. При отказах сохраняется прежнее поведение
с использованием старых доступных курсов. Это не поток биржевых котировок.

## Проверка перед выкладкой

При подготовке обновления на Python 3.14 с новыми зависимостями прошли 132 теста,
`pip check` и проверка конфигурации Compose. Отдельная проверка публичных API
получила 177 курсов, включая USD, EUR, RUB, UZS, BTC и USDT.
Она использовала фиктивный Telegram-токен, без CoinCap-ключа и без доступа к базе.

В синтетическом сценарии 100 одновременных принудительных обновлений с имитацией
загрузки длительностью 10 мс число загрузок уменьшилось со 100 до 1.
Это проверка устранения дублирования, а не оценка ускорения на проде.

Локально в отдельном окружении Python 3.14:

```sh
python3.14 -m venv /tmp/otc-check
/tmp/otc-check/bin/python -m pip install -r requirements-dev.txt
/tmp/otc-check/bin/python -m pip check
/tmp/otc-check/bin/python -m pytest -q
```

Тесты подставляют фиктивный токен, используют временные базы и подменяют запросы Telegram.
Они не проверяют реальный токен, доступность API или права Telegram-бота.

На машине с работающим Docker сначала собрать кандидат и проверить его без продовых томов:

```sh
docker build -t otc-bot:1.8.4 .
docker run --rm --entrypoint sh otc-bot:1.8.4 -c 'python -m pip install -r requirements-dev.txt && python -m pip check && python -m pytest -q'
```

Это отдельный тестовый контейнер: polling не запускается, продовая база не подключается.
В ходе подготовки обновления Docker daemon на рабочей машине был недоступен,
поэтому контейнерную проверку нужно выполнить перед выкладкой.

Перед заменой продового контейнера сохранить текущий образ и согласованную резервную
копию базы через SQLite backup API или существующий механизм `backup_db`.
Не копировать только `.db` при работающем WAL: свежие записи могут находиться в WAL-файле.
Сохранять прежний путь к базе и подключённый том `./data:/app/data`.
Выкладывать один экземпляр: два polling-процесса с одним токеном конфликтуют.

После замены проверить `/start`, `100 USD`, `100 USD EUR`, inline-конвертацию,
настройки группы и `/health`. Для отката вернуть предыдущий образ с тем же томом:
миграций базы в этом обновлении нет.

## Возможности Telegram для следующих обновлений

Ничего из перечисленного ниже не включено в этом релизе.

1. **Копирование результата.** `CopyTextButton` копирует сумму одним нажатием;
   ограничение — 1–256 символов, поэтому подходит для одной конвертации.
   [Документация](https://core.telegram.org/bots/api#copytextbutton).
2. **Быстрый переход к inline-конвертации.** `switch_inline_query_chosen_chat`
   открывает выбор чата с заранее заполненным запросом. Требуется включённый inline-режим.
   [Документация](https://core.telegram.org/bots/api#switchinlinequerychosenchat).
3. **Гостевой режим.** Конвертация по вызову пользователя в чате без добавления бота.
   Потребуются отдельный обработчик `guest_message`, ответ `answerGuestQuery`
   и настройка гостевого режима в BotFather.
   [Документация](https://core.telegram.org/bots/features#guest-bots).
4. **Личные ответы внутри группы.** Ephemeral-сообщения позволяют показать расчёт
   только инициатору и не засорять общий чат. Нужны отдельная настройка поведения
   и проверка работы с клиентами Telegram.
   [Документация](https://core.telegram.org/bots/features#ephemeral-messages).
5. **Rich Messages.** Таблицы курсов и структурированные блоки вместо длинных
   текстовых списков; потребуется переработка форматирования и проверка отображения.
   [Документация](https://core.telegram.org/bots/api#sendrichmessage).

Для этого бота первыми полезнее копирование и быстрый inline-вызов.
Цветные кнопки и custom emoji уже используются в текущем коде.
